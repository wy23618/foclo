# 注销与旧备份恢复保护

实现：管理员命令必须提供独立删除记录目录，不接受缺失记录目录作为“没有注销”。Linux目录必须由执行管理员持有、0700，记录0600；Windows需先由当前管理员在受限目录设置ACL。生产API用户不能读取云端root目录 `/var/lib/yotick-deletion-ledger`。

每份记录只含版本、申请UUID、账号UUID和批准时间，不含OpenID或业务内容。用户注销申请仍仅为待审；只有管理员核实并以原申请UUID确认后，才写“批准删除意图”。记录用独占创建和fsync，在数据库删除事务提交前持久化；创建失败、损坏记录或不同账号复用申请ID均拒绝删除。重复确认保留原批准记录。

批准意图表示已经批准的删除工作，事务失败或进程中断后仍应重试，不自动取消该批准。它不是“已完成”的证明。旧数据库恢复后，即使备份中尚没有注销申请，也能按批准记录定位原账号UUID并清除其身份、会话、事实和同步资料。新注册生成的新UUID不受旧记录影响。

`reconcileDeletionLedger` 只允许 `yotick_restore_*` 隔离库，逐账号事务处理，重复执行不会影响其他账号；拒绝对正在运行的yotick库执行。缺失初始化标记、非法文件或损坏记录时恢复流程停止，不能通过忽略记录继续上线。管理员应先人工确认取得了外部保存的最新完整删除记录；当前脚本结果明确 `ledgerFreshnessExternallyVerified:false`，不冒充已检查外部最新性。

云端管理可通过Unix socket和root/postgres精确peer映射执行。此通道不用网络口令，不改变业务网络连接的强制TLS；yotick业务OS用户未加入映射。每日数据库备份不能作为唯一删除记录来源。独立记录和其当前清单须同步保存到另一故障域，丢失或无法确认最新记录时不能切换恢复库。

本机真实PostgreSQL回归已验证：故障发生在删除事务末尾时全部数据库资料回滚，批准记录保留；重试完成删除；再恢复注销申请出现之前的旧快照，删除记录清除原账号而保留另一账号，重复恢复处理无额外删除。只用生成样本，没有真实注销执行。

云端当前已初始化空记录目录，恢复演练会执行该门禁。持续异地记录复制、运营审核/告知和正式注销启用仍待环境配置，因此不称注销运营全流程已完成。
