# 账号、设备与本地记录的一致性

更新：2026-10-26。

## 数据归属

- 未登录记录属于当前设备的游客空间。不同设备的游客记录不会自动互通。
- 登录后的本机数据是该账号的独立缓存，包含本机尚未上传的更改。空间按账号对应的 spaceId、generation 与可选 localEpoch 分开。
- 同一设备切换 A/B 账号，不移动项目、记录或待上传队列；重新登录原账号后继续原队列。游客记录进入某个账号前必须单独确认，A 的选择不替 B 确认。
- 同账号多设备允许离线使用，所以缓存可能暂时不同。联网、完成上传下载且没有未解决冲突后，应与同一云端状态一致。前台每 30 秒检查更新，回到前台立即同步，后台暂停轮询。
- 进行中的计时留在创建它的设备上，完成后上传；不能把另一设备暂时看不到该计时称为丢失。
- 新增账号与记录页的刷新入口，以及账号、记录、统计页下拉刷新。刷新等待上传下载完成后再读本机显示；失败保留原数据显示，不把失败称为成功。登录也等待首轮下载。
- 登录设备开始计时前检查账号内其他近期在线设备。开始后上报短期计时状态，前台同步时更新，结束后清除。两个设备几乎同时开始时，后续上报和前台更新仍会提醒；不远程终止或删除任何计时。
- 计时状态两分钟未续报即过期，不作为专注记录或持久业务备份。离线、后台冻结、未升级的客户端或游客模式不能可靠检测；提示说明限制，允许用户明确选择继续本机计时。
- PostgreSQL 增加 006_focus_presence.sql，Cloudflare 启动 schema 幂等创建独立状态表。该表不改变账号或事实表。

## 同步与恢复约束

- 同批次后续变更读取前面尚未提交的变更，新增后删除以删除为准；较旧 serverVersion 不能覆盖较新版本。
- 对旧客户端遗留的“云端影子已删除、本机事实仍存在”进行自检。无本机待上传修改时移除残留；有修改时保留事实并生成冲突，不静默抹掉离线工作。
- 切换账号立即取消旧请求；迟到的成功、失败和刷新结果不能污染新账号界面、凭据或数据。
- 访客导入的确认绑定当时的账号和代次；确认窗口打开后或上传期间切换账号，原确认不能用于新账号，必须重新确认。
- 重新下载前必须联网同步成功，且没有未上传修改、冲突或进行中计时。全量数据先写不可见视图，完成并校验后切换指针，保留之前的视图供恢复；断网不先清空唯一缓存。
- 访客导入遵循 KEEP_ACCOUNT：同 ID 与完全相同事实不重复导入，账号删除标记不被旧游客副本复活，账号现有项目资料优先。中断重试沿用导入任务与回执。
- 时间交叠不等于重复。独立记录保留；导入前提示与账号已有实际专注区间的交叠，扣除暂停，不自动删记录或改变统计口径。

## 面向用户的说明

访客导入明确显示来源设备、目标账号尾号、项目与记录数量，并使用“存入账号 / 留在本机”。分别解释是否上传、其他设备能否看到、游客原副本是否保留，以及账号已有记录仍正常同步。

冲突页面区分账号云端版本与本机未同步修改。选择后先解释“按云端更新本机”或“提交本机修改到账号”的影响；只有项目名称冲突才要求改名。删除与恢复的影响另行说明，原冲突资料保留。

## 验证入口与发布边界

前端：`node --test tests/*.test.js`。后端：在 server 中运行 `npm test`。重点覆盖 sync-local、account-switch、request、snapshot-view、guest-pending、login-flow、sync-copy 与 guest-merge，真实 PostgreSQL 集成测试另覆盖双客户端、HTTP 归属校验和导入重试。

这些是客户端修复。电脑开发者工具使用本地源码；手机上的已发布版本只有上传、审核并发布相应小程序包后才会使用新逻辑。不得将本机验收称为所有手机已更新。
