# 记录归属与保存位置

账号决定归属，设备或服务器决定保存位置。账号记录和云端记录不能作为两套独立业务数据展示。

2026-10-12 更新：开发者工具默认与手机开发预览、体验版连接同一个云端账号服务。电脑 API 仅供显式指定地址的独立测试使用。开发者工具第一次切换时保留旧测试账号空间和队列，重新微信登录后使用独立的云端缓存空间，旧测试更改不会提交到云端。

游客保存入口先依据已同步的账号项目、记录和删除标记进行本机比较。已保存的内容、相同事实以及已删除项目下的记录不计入待保存数量。没有待保存内容时不显示入口、不弹确认；网络未核对成功时不自动询问。比较不会在用户同意前上传游客内容，最终合并仍由云端 KEEP_ACCOUNT 策略核定。

| 内容 | 归属 | 本机 | 服务器 |
| --- | --- | --- | --- |
| 游客记录 | 这台设备的游客空间 | 独立 guest 命名空间 | 确认保存到账号前不上传 |
| 账号记录 | 实际微信登录识别的账号 | 当前账号的离线副本及待上传更改 | 同一账号已保存的记录 |
| 备份文件 | 导出时所选空间的快照 | 用户主动保存的文件 | 不参与自动同步 |

## 操作边界

- 登录切换到账号空间，不自动划入游客记录。迁移须明确确认。
- 游客保存保留原副本，同一事实因此可以同时存在于游客空间和账号空间。成功整理的游客版本隐藏入口。重复事实自动跳过，删除标记自动尊重，用户不再逐项选择。
- 自动整理在服务器事务中读取最新账号记录：同 ID 项目沿用账号资料；同名同父项目复用；不同父项目的重名新项目自动改名保留层级。已删除或旧代际项目连同源子树跳过。记录按已有 ID 和映射后项目、起止时间、时长、目标、暂停内容识别重复；已删除记录也参与识别，不恢复、不增加统计。
- 自动整理必须由支持 KEEP_ACCOUNT 的服务处理；旧服务无标识时客户端保留记录并拒绝提交。独立维护工具的明确人工映射仍可使用旧协议，普通用户的游客保存不使用它。
- 本机账号副本和服务器可能暂时不同：离线更改、待上传任务、其他设备更改尚未下载。只有同步成功后才应声称账号已保存。
- 退出切回游客空间，账号本机副本和待上传任务保留，停止该账号同步。再次登录同一账号继续使用它们。
- 删除账号项目或单条记录会同步删除，不删除游客副本或独立备份文件。
- 游客清空仅允许游客空间。账号清空走专用接口并更换数据代际，旧本机代际隔离保留，不能作为当前账号重新上传。
- 重新下载账号记录必须先确认没有未上传内容或待确认更改；新建本机账号空间下载当前服务器内容，旧副本保留。
- 日常备份导出当前使用空间在本机的记录，不承诺包含尚未下载的服务器内容。恢复目标也是当前空间，登录后恢复新增内容会上传。修复文件另含待同步任务，仅供维护使用。
- 头像昵称是每个账号在本机的展示资料，与专注记录同步分开。

对应实现：sync/accounts.js、storage/account-adapter.js、sync/worker.js、sync/migration.js、core/service.js。不能为了消除提示而自动覆盖账号记录、清空游客副本或重复统计。
