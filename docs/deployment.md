# YoTick 云端部署与发布准备

更新时间：2026-10-09。按用户后续决定，部署目标改为自有通用后端与阿里云 ECS/PostgreSQL；原执行文档里的 CloudBase 是早期默认方案，不再是当前部署目标。服务器内部部署及临时公网 HTTPS 手机登录/同步验收已完成；正式域名、备案、体验版与完整设备专项仍未完成，不能称为可发布版本。

## 当前实际部署

- 阿里云杭州 ECS：Ubuntu 22.04、2 vCPU、2 GiB、40 GiB，公网 IPv4 `121.199.74.171`。2026-10-08 控制台只读核对显示实例健康“正常”、付费类型“按量”。免费试用按量资源不符合大陆 ICP 备案资源条件；超出免费额度可能产生按量费用。没有转包月、没有购买或升级资源。
- Node.js 24、PostgreSQL 17。API 由 `yotick.service` 管理，仅绑定 `127.0.0.1:3000`；PostgreSQL 只绑定回环地址，数据库不向公网开放。服务用非登录账号运行，数据库 TLS 验证、最小权限和自动启动均已检查。
- 2026-10-08 Workbench 实测 API/PG回环监听，SSH 22对公网监听；用户确认后为临时开发IP HTTPS仅开放TCP 80/443，未开放3389或API/数据库端口。SSH 22和ICMP规则仍在。
- 业务结构迁移至17张表；云端现有数据是电脑测试快照，不是真实用户数据。每日 AES-GCM 加密备份、隔离库恢复、旧游标失效和整机重启恢复均有实测记录。
- 微信 `wx.login` 凭据已在云端成功换取同一测试账号身份；这是微信身份交换验证，不代表手机已通过公网访问云端。
- 微信开发版手机已通过临时公网IP HTTPS完成扫码、微信登录和同步验收；DevTools继续使用回环，trial/release不选择该IP。该地址及短期证书只供开发验收，正式版仍需域名、备案和微信合法域名设置。

详细配置与命令见[阿里云部署证据](ecs-deployment.md)、[后端交付包](backend-bundle.md)、[费用估算](cloud-budget.md)和[备份恢复说明](backup-recovery.md)。不要把本机调试 `.env`、AppSecret、数据库凭证或备份密钥放进小程序包或聊天。

## 正式公网接入的先决条件

1. 注册由用户真实信息持有的域名。域名名称、实名认证模板和实际价格以注册控制台为准；不得猜测或代填身份资料。
2. 若服务器在中国内地，使用符合备案条件的云产品完成 ICP 备案。当前 ECS 试用按量付费不满足备案要求；阿里云备案资源要求包含中国内地节点、包年包月时长超过3个月（续费累计可计入）和公网带宽。订单与续费价格需在购买前查看。
3. 域名解析到服务器后，为域名申请并安装有效 HTTPS 证书，配置 Nginx/Caddy 等反向代理到 `127.0.0.1:3000`。仅在防火墙和安全组审核后开放必要的 80/443；PostgreSQL 仍保持内网/回环，不开放公网。
4. 在微信小程序后台登记 HTTPS 请求域名，将小程序正式配置指向 `https://<域名>/api/v1`，生成新预览包。不得把临时 IP 或绕过证书校验的调试方案当作上线配置。

官方限制：[阿里云 ECS 免费试用](https://help.aliyun.com/zh/ecs/user-guide/ecs-free-trial)、[阿里云备案前准备](https://help.aliyun.com/zh/icp-filing/basic-icp-service/user-guide/overview)、[小程序网络域名规则](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)。购买/升级/注册与公开发布按用户授权范围执行，任何订单以控制台最终金额为准。

没有域名期间，另有一条仅供开发真机验收的临时公网IP HTTPS路径，证书有效期约6天且需自动续期，不满足正式发布条件。用户确认后已开放公网TCP 80/443，Nginx/Certbot已部署，短期证书签发成功，外部未认证API返回预期401。开发手机配置已指向临时地址，仍需手机真机验证；生产版本继续不配置此IP。实施记录和限制见[临时IP HTTPS手机测试](temporary-ip-https-test.md)。

## 域名与备案到位后的切换顺序

1. 核对源端电脑空间与当前账号，暂停旧端新增写入；创建新的最终快照，保留未上传任务、冲突副本、删除回执和迁移映射。不可把两端各自独立写入当成已合并。
2. 在隔离库恢复并对比项目、记录、暂停、操作回执、tombstone、迁移工作和摘要；设置新 `restore_epoch`，确认旧游标被拒后再准备切换。保留旧库和旧服务作为回退源。
3. 完成公网 HTTPS 与微信域名配置后，用真实手机逐项验收登录、同步、离线重开与补传、响应丢失重试、双设备并发、删除后旧设备返回、迁移中断和全量恢复。用户已确认的手机/平板基础操作不重复要求，但新云端地址仍需验。
4. 设置并实际演练持续异地加密备份、删除意图记录副本、告警接收人和恢复流程。现阶段服务器已有本地加密日备份及人工复制到电脑的副本，尚无持续异地复制或外部告警。
5. 用实际微信体验版验证正式包、隐私说明、账号注销办理流程、兼容与回退。真实运营主体、联系方式和最终隐私告知必须由运营者提供；最终公开发布需完成全部关键验收。
