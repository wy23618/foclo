## 1. 用户已经确定的方向

1. 使用微信／腾讯云云开发体系承载后端，默认选择 CloudBase 云托管。
2. 后端代码、账号体系、接口、数据模型采用通用设计，让未来 App 与小程序共用。
3. 数据库采用标准 PostgreSQL，初期由云平台托管；“数据库自己的”指表结构、数据与业务规则由我们管理，不要求另外租机器自行维护数据库。
4. 小程序保留离线计时、本地保存和本地统计。网络、后端冷启动或同步故障不能阻塞开始、暂停、恢复和结束计时。
5. 第一版完成微信登录、历史数据迁移、项目和已完成记录双向同步。
6. 云函数不是必须组件。云托管运行完整后端，承担登录、保存和同步工作。未来若改用 HTTP 云函数，须保持同一业务代码与接口；不得擅自更换已确定的默认部署方式。
7. 云托管和云函数都可能冷启动；不要宣称云托管必然更快，也不要保证任何情况下完全无延迟。

默认架构：

```text
小程序（本机计时、事实存储、待同步队列）   未来 App
                  │                       │
                  └──── HTTPS /api/v1 ─────┘
                              │
                      YoTick 自有后端
                    CloudBase 云托管运行
                              │
                   标准 PostgreSQL 连接
                              │
                     托管 PostgreSQL
```

后端保持无状态：实例内存和容器本地磁盘均不是持久事实来源。登录会话、操作回执和同步状态放在数据库中。

## 2. 执行边界与协作要求

- 本文授权的是拟定实施范围；接到“按本文执行”后，AI 可自主完成本地设计、代码、测试和部署资料。

- 先完成可独立进行的本地工作，缺少云端配置时集中列出所缺信息。不得因缺少密钥而停留在口头方案，也不得宣称真实登录或云部署已验证。
- 密钥通过安全配置提供，不要求用户在聊天中粘贴数据库密码、AppSecret 或签名密钥。不读取或打印与任务无关的秘密。
- 保留现有功能和外观。无需为了同步重新设计计时页或重写统计图表。
- 根据实际代码修订字段细节时，在决策记录中说明理由；不得静默缩减离线能力、数据保全或验收要求。
- 不自动创建其他用户聊天；未获授权时不派生代理。是否并行执行遵循所在环境的用户与仓库指令。
- 持续维护进度清单，区分“已实现、模拟验证、实际验证、待用户配置”。

- 备份合并拒绝同 ID 不同内容；当前 import 有约 650 KiB 的单次提交安全限制。
- 当前 `clearAllData` 删除广泛的 yotick 前缀键，并重建本机空间；引入账号键后必须审计，避免清掉登录或其他账号。
- 小程序根目录为项目根。新增后端、依赖、文档与测试必须处理打包排除。

## 4. 第一版业务范围

### 4.1 需要同步

- 项目：ID、名称、父子关系、显示排序、归档、简称、明确颜色。
- 已完成专注记录：ID、项目、开始结束、目标时长、有效时长、完整暂停明细。

- 项目删除与记录删除。

### 4.2 保留本机

- ACTIVE 专注与休息计时，以及当前计时控制权。
- 主题 `theme` / `lightTheme`、屏幕常亮、当前图表选择、`statsPreset`、`timeSlotScaleMinutes` 等显示偏好。
- `lastProjectId`、`lastStartMode`、本机休息轮次、欢迎标记。
- 本地日/项目索引及统计结果缓存。

偏好统一建立字段归属表与校验表。新字段默认不上传，明确归属后才加入白名单。对引用已删除项目的本机偏好做清理。

### 4.3 本期不做

- 跨设备继续进行中的计时、远程暂停或抢占控制权。
- 多人共享项目、团队空间、社交排行榜。
- App 页面、安装包与应用商店发布。
- 全量历史的服务端统计引擎；第一版统计继续本地计算。
- 引入 Redis、消息队列、微服务等非必要基础设施。

两台设备可以各自离线专注。完成后均保留记录；时间重叠不自动合并或删除。不承诺全账号只有一个活动会话。

## 6. 账号与本地隔离

### 6.1 云端身份

YoTick 使用独立 `userId`。身份表保存 `provider`、`appId`、外部 subject 与 userId，对 `(provider, appId, subject)` 建唯一约束。

小程序登录：客户端 `wx.login` 得到一次性 code → 后端校验微信身份 → 创建或查找 YoTick 用户 → 返回业务登录凭证。

- 不相信客户端提供的 openid、userId 或空间归属。
- AppSecret 与 session_key 不下发到客户端。
- 登录凭证由安全随机数生成；建议短期 access token 加轮换 refresh token。具体时效写入配置与文档。
- refresh token 只保存哈希，支持撤销、退出与重用检测；处理响应丢失及客户端并发刷新，避免用户意外失去登录。
- 登录过期时暂停同步而不是删除本地数据；同账号重新登录后续传。
- App 登录方式留适配入口，但不实现虚假的 App 微信登录。
- 小程序与 App OpenID 不同。未来通过经过验证的 UnionID 或显式账号绑定关联，不能按昵称、手机号输入或“看起来相同”自动合并。

### 6.2 空间模型

第一版一个用户一个账号空间：`spaceId`、`generation`、`changeSeq`。

- `generation` 是数据空间代次，账号清空时递增，用于拒绝旧设备操作。
- 现有本机 `meta.id` 与账号空间 ID 明确映射，不当作可信身份。
- 本地 schema、云端 schema、API 版本分别维护。

### 6.3 本地命名空间

为游客和每个账号保存独立事实、偏好、索引、outbox、同步元数据和冲突数据。底层 adapter 包装成当前空间视图，减少业务代码大范围更换键。

- 首次升级先把旧无命名空间键识别为游客数据，采用可恢复迁移标记，验证新副本后才处理旧副本。
- 全局只保存当前账号引用、安装设备 ID 与必要登录配置；不能因“清空当前空间”删除其他空间。
- 同步 worker 持有 userId/spaceId/generation 和客户端切换代次；账号切换后到达的旧响应一律不应用到当前页面或账号。
- 退出时终止旧 worker、请求和订阅，保留其待上传数据。
- 活动专注或休息期间禁止空间切换，提示先结束。恢复账号可准备，但不替换正在计时的事实空间。
- 切换后重新初始化 service 与配色缓存，重建统计基准。

## 7. PostgreSQL 数据模型

使用 SQL 迁移脚本，至少覆盖以下表。字段可细化，但职责与约束不能遗漏。

| 表 | 关键职责 |
| --- | --- |
| users | 内部用户与账号状态 |
| auth_identities | 外部登录身份关联与唯一约束 |
| auth_sessions | 设备会话、凭证哈希、撤销与刷新 |
| spaces | 用户空间、generation、事务内递增 changeSeq |
| projects | 项目事实、serverVersion、deletedAt |
| study_sessions | COMPLETED 记录、originDeviceId、serverVersion、deletedAt |
| pauses | 暂停明细，随所属专注整体提交 |
| account_preferences | 白名单偏好及版本 |
| sync_operations | 操作 ID、请求摘要、处理结果，防重复与 ID 复用 |
| sync_changes | 按空间和代次排序的提交后变更日志 |
| import_jobs / import_items | 迁移计划、分块、状态与恢复进度 |

要求：

1. 业务实体按空间与实体 ID 唯一，原离线 UUID 原则上保留。暂停同样校验所属空间和会话。
2. 跨实体外键带空间限制，防止一条记录引用另一个用户的项目。
3. 项目名称唯一性与当前 JS 规则一致，包括归档项目；软删除项目不占有效名称。
4. 保留客户端事件时间为 epoch 整秒与 UTC+8 统计语义。服务器接收时间另存，不能用服务器时间重写历史时长。
5. 校验持续时长、结束顺序、暂停边界、重叠暂停、项目引用与目标时长，复用或等价实现现有算法；不信任客户端 duration。
6. 项目树无环、父节点有效；整组排序、子树归档/恢复/删除为原子业务操作。
7. 排序不直接把多设备本机 `nextCreationOrder` 当服务器全局顺序。设计稳定 orderKey 或服务端排序号，并适配本地 creationOrder；冲突校验覆盖整个相关排序组。
8. 已完成记录第一版视为内容不可变，只允许新增与删除；同 ID 不同内容返回冲突。
9. `lastUsedAtSec` 若同步，作为独立使用元数据单调合并，不因一次计时开始覆盖整个项目或引起改名冲突。
10. 所有删除先保留 tombstone；v1 不主动清理 tombstone 与幂等回执。需要清理时先实施保留期、过期游标和旧操作拒绝机制。

事务设计：业务事实、相关实体版本、changeSeq、变更日志和幂等回执同一事务提交。建议每次空间写入先锁 spaces 行，分配事务内递增序号，再提交；保证变更序号与可见提交一致，避免普通数据库 sequence 先分配后提交导致漏拉。

小规模第一版空间内串行写入可接受。不要把本地 dataRevision 整包上传作为云端版本。

## 8. 接口契约

路径以 `/api/v1` 开头，提供 OpenAPI、请求/响应示例和客户端错误映射。

| 方法与路径 | 作用 |
| --- | --- |
| POST /auth/wechat-mini | code 换 YoTick 登录态 |
| POST /auth/refresh | 刷新业务登录态 |
| POST /auth/logout | 撤销当前会话 |
| GET /me | 账号、空间、代次与能力信息 |
| POST /sync/push | 有序业务操作上传 |
| GET /sync/pull | 按游标分页拉取变化 |
| POST /sync/snapshots | 建立一致全量快照 |
| GET /sync/snapshots/:id | 分页读取快照 |
| POST /imports/preview | 分块迁移资料完成后生成预览 |
| POST /imports | 创建迁移任务 |
| PUT /imports/:id/chunks/:index | 幂等上传分块 |
| GET /imports/:id | 查询迁移进度 |
| POST /imports/:id/commit | 校验并发布迁移内容 |
| POST /data/clear | 明确确认后清空账号事实并增加 generation |
| POST /exports | 创建账号导出任务 |
| GET /exports/:id | 查询或分页下载导出结果 |
| GET /health/live、GET /health/ready | 进程与依赖健康检查 |

预览路径与分块任务流程执行时可整理，但必须支持大数据分块，不能把全部 JSON 强塞入单次请求。

push 必要字段：protocolVersion、spaceId、generation、deviceId；操作项包含 operationId、kind、entityId、baseServerVersion 或依赖回执、payload。

初始批量建议每批最多 50 个操作和 256 KiB JSON，单实体超限返回明确错误。根据平台与本机限制实测后调整。冲突、成功、可重试失败逐项返回，并明确是否已提交；不能让客户端猜测整批结果。

业务操作建议包含 project.create / patch / reorder / archive / restore / deleteSubtree、session.createCompleted / delete、prefs.patch。

- 不直接暴露任意存储 key、任意 SQL 或任意对象写入接口。
- 每个操作在服务端核验空间所有权。
- 同 operationId 同请求摘要返回原回执；同 ID 不同摘要返回 OPERATION_ID_REUSED。
- 暂时失败可重试，业务冲突需要新操作 ID 和明确解决；不把瞬时错误永久缓存成成功回执。
- 分组排序、子树操作携带相关实体预期版本，校验整组，失败不能只修改半组。
- 错误至少区分 AUTH_REQUIRED、VERSION_CONFLICT、NAME_CONFLICT、ENTITY_DELETED、GENERATION_MISMATCH、CURSOR_EXPIRED、DEPENDENCY_PENDING、PAYLOAD_TOO_LARGE、RETRYABLE_ERROR。
- bigint 序号与版本如可能超过 JS 安全整数，协议统一用十进制字符串。
- 限制大小、分页数量、迁移任务寿命、请求频率，日志不记录凭证和完整用户事实。

## 9. 本地 outbox 与同步算法

### 9.1 写入可靠性

持久保存业务变更及对应 outbox 项。采用现有可恢复提交协议扩展，保证崩溃重放后同时拥有事实和待上传任务。

- 生成任务在业务层，不能在每次 storage.set 时盲目上传；排除索引、commit 描述、ACTIVE 心跳和设备偏好。
- 完成记录的任务覆盖 stop、自动到期、回前台结算和恢复流程，使用稳定操作 ID 防重复。
- 保留本地 revision，与 baseServerVersion/云端影子副本分别存储。
- 同步确认、规范化后的服务端事实、outbox 确认与游标更新同样做可恢复提交。
- 未得到持久确认不删除任务。崩溃或响应丢失后使用同一操作 ID 和相同 payload 重试。

### 9.2 连续离线修改

同项目离线改名、改色、排序不能都带同一个旧服务端版本然后无序上传。

- 每个实体/排序组按依赖顺序处理。未发送任务允许安全合并；已发送或结果不确定的任务冻结 ID 和内容。
- 后续任务在前序持久确认后确定其基准版本；明确依赖未满足则暂缓。
- 同步确认不能覆盖确认之后产生的新本地修改。
- 本地项目先创建后产生完成记录，记录任务依赖项目创建成功。
- 项目从未同步且后来删除时，只有确认所有操作从未发送，才能安全消除创建/删除链。

### 9.3 worker

- 单账号空间一个协调 worker，同步调用合并，不重入。
- 本地启动完成后异步调度，监听前台、网络恢复和业务事件；小程序后台不承诺持续运行。
- 同步周期先拉取并保存云端影子状态，再上传无冲突依赖项，最后拉取到本轮边界；具体调度须在协议文档中写清。
- 指数退避加随机抖动、超时和可取消请求；前台适度重试，避免固定高频轮询。
- 401 触发一次受协调的刷新，失败进入“需重新登录”；不删 outbox。
- 网络慢时任务后台排队，计时命令从不 await 网络响应。

### 9.4 拉取与快照

- 第一页固定 snapshotUpperSeq，后续页面只拉取 cursor < seq <= upperSeq。游标有签名/校验，绑定空间、generation 与协议版本。
- 收到页面后先持久保存事实/冲突资料及新游标，再继续下一页。
- 拉取到本机未同步实体，更新影子副本并检查冲突，不静默覆盖本地改动。
- 全量快照建立一致的事实视图和截止序号，使用有期限的快照令牌或物化 staging；不能分页读不断变化的表后直接声称一致。
- CURSOR_EXPIRED 先保全本地待上传与冲突数据，再全量恢复。不得先清空 outbox。
- 日/项目索引在业务队列中增量更新；全量时分批重建，并最后切换有效视图。
- service 缓存和配色缓存一起刷新，页面按影响范围通知，避免每一页全图重算。

## 10. 冲突与删除规则

| 情况 | 处理 |
| --- | --- |
| 不同 UUID 的新增记录 | 合并；即使时间重叠也不自动删除 |
| 同 UUID 同内容 | 去重 |
| 同 UUID 不同内容 | 保存双方资料，显示冲突 |
| 两设备修改同项目 | 服务端 CAS 检查；冲突进入可操作列表 |
| 同名不同 ID 项目 | 名称冲突；用户可改名或显式映射 |
| 删除后旧设备上传旧副本 | tombstone 拒绝旧修改，禁止自动复活 |
| 删除项目时另一设备正计时 | 保留活动记录及其最小项目上下文；完成后进入恢复/重新归属流程 |
| 登录过期、断网 | 本地继续使用，同步暂停 |
| 账号数据清空 | generation 递增，旧代次任务隔离，禁止自动再次上传 |

冲突中心至少提供查看双方差异、采用云端版本、基于当前云端版本重新提交本地改动的能力；采用云端版本前保留恢复副本。

记录引用已删除项目时，不静默丢弃、创建公开幽灵项目或把孤儿会话塞入现有项目索引。提供“另建项目保存”或“选择有效项目保存”等明确操作，并在事务内处理归属。

本机 ACTIVE 依赖的项目收到删除时，不直接让 service.validateSession 失败。可暂留隔离上下文并推迟应用删除；全空间拉取游标可在相关变更已持久保存为待处理冲突后推进。

## 11. 原有数据迁移与备份

### 11.1 本地结构升级

升级顺序：恢复旧提交 → 校验旧事实 → 制作可读快照 → 分批复制游客命名空间 → 校验数量/ID/事实摘要 → 持久切换标记。

复制中断后可续传。旧版本无法理解新结构时，要在发布与回退文档中说明；不可承诺回退安装旧代码一定无损。

### 11.2 游客到账号迁移

- 登录与上传本机历史是两个动作。用户明确选择合并后才迁移游客内容。
- 活动专注或休息时暂缓空间切换与迁移发布。
- 建立任务 ID、来源空间、稳定源快照、分块摘要、处理进度。
- 云端为空按原 ID 导入；云端已有数据先预览重复、冲突与最终映射。
- 同名不同 ID 项目不按名字自动合并；用户显式映射后，同时重写父子引用及会话归属。
- 同 ID 不同内容必须处理冲突。确需新 ID 时保存来源映射和恢复资料。
- 迁移 staging 先不可见；全部验证后原子发布或在可恢复 job 机制下保持其他设备一致视图。
- 内容较大时不得长时间持有整个空间锁或用一份巨型事务描述。实现有上限的分块与明确提交边界。
- 迁移后校验项目数、会话数、暂停数、ID、时长和摘要。游客原副本保留直到确认恢复能力与用户选择。
- 现有 createBackup / validate / rebuild 逻辑可复用，但 importBackup 不是日常同步引擎。

### 11.3 备份与数据操作

- 保留本机导出与恢复；格式升级兼容 formatVersion 1。
- 账号空间导入会生成同步任务，按普通重复/冲突规则处理，不绕过 tombstone。
- 区分“清除本机缓存”“删除账号全部数据”“退出登录”。
- 未上传内容存在时阻止直接清缓存，提供同步或导出保全路径。
- 云端清空需要重新确认、generation 推进、回执持久化。其他设备旧数据转为隔离恢复副本，不自动回灌。
- 第一版完成账号数据导出和删除数据入口。发布前明确账号注销入口与服务端处理流程，清理所有关联身份并撤销会话；正式用户数据保留政策不能用任意猜测值。

## 12. 界面与流畅度

保持现有风格，设置页与设置组件都增加“账号与同步”。

展示状态：未登录、正在同步、已同步及时间、待上传数量、离线、需要重新登录、冲突待处理、同步失败。

例：

- “数据保存在本机，登录后可跨设备同步。”
- “已保存在本机，联网后同步。”
- “这项内容在另一台设备上有修改，请选择保留方式。”

实现要求：

1. 开始、暂停、恢复、结束命令只等待可靠本地持久化，不等待网络。
2. 现有记录与统计优先本地展示，后台同步完成后更新。
3. 首次登录、迁移与全量下载显示阶段与数量；可恢复，不用假百分比。
4. 同步期间只更新相关页面；避免大型同步 JSON 解析、全注册表复制和全图重绘长期占用主线程。
5. 分批处理、让出事件循环、合并事件与去抖通知。合理维护当天统计基准。
6. 真机测量上线前后操作耗时和帧表现，记录数据规模、机型、网络与统计方式。
7. 性能目标以“同步不增加网络等待、无明显新增卡顿”为准；不能在没有测量时宣称完全不卡。

建议性能样本：500 个项目、10,000 条记录及典型暂停数组；样本先计算实际字节与本地存储上限。若容量超出平台限制，应验证明确容量提示与分层缓存方案，不把存储失败伪装为同步成功。

## 13. 分阶段执行与完成条件

### 阶段 A：审计与设计冻结

任务：读取所有仓库指令；核实功能、数据形状、写入路径、打包范围、计时结算、备份流程。建立字段归属、账号模型、API、数据库模型和冲突策略。

产物：architecture-decisions、OpenAPI 初稿、数据库设计、执行清单、现有行为基线。

完成条件：自动结算、颜色、偏好、删除、清空、恢复均有明确同步策略；不能只覆盖 happy path。

### 阶段 B：本地后端与数据库

任务：服务框架、配置校验、SQL 迁移、登录适配、会话、项目/记录操作、幂等回执、变更日志、事务、分页与快照。

产物：可运行后端、数据库迁移、容器配置、接口契约与集成测试。

完成条件：两个模拟设备通过真实 PostgreSQL 验证新增、冲突、重复重试与删除；不能只用内存数据库验证事务。

真实微信凭证未提供时测试替身可继续开发，其结果单独注明。

### 阶段 C：本地隔离与可靠队列

任务：游客升级、账号 adapter、outbox、影子版本、可恢复提交、worker、退避、切换隔离、索引与缓存刷新。

完成条件：在关键写入点注入故障并重启，事实与队列不丢；不影响离线计时。

### 阶段 D：接入登录、迁移与界面

任务：实际登录交互、账号页、同步状态、冲突中心、迁移预览、分块续传、备份适配、数据清理与说明文案。

完成条件：本地双客户端模拟完整流程；账户切换、刷新凭证、迁移失败与恢复均有可操作路径。

### 阶段 E：云端测试环境

任务：核实当前 CloudBase 产品能力与价格，提供配置方案与费用清单；在用户授权资源内部署测试服务、数据库、HTTPS 与必要请求域名。

完成条件：真实微信登录、真机联网、双设备同步通过；无调试身份后门，密钥未打包，数据库非客户端公开读写。

### 阶段 F：发布准备与小范围验收

任务：备份/恢复演练、性能测量、错误监测、资源上限、版本兼容、发布及回退步骤；体验版试用后整理实际结果。

完成条件：验收矩阵关键项通过，未验证项明确列出；正式发布按用户授权执行。

不得跳过 A-C 直接修改全部页面并连接正式数据库。

## 14. 必须执行的验收矩阵

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| T01 | A 新建项目并完成记录，B 拉取 | ID、层级、颜色、时长与暂停一致 |
| T02 | B 删除记录，A 曾离线 | A 删除同步且旧副本不复活 |
| T03 | 网络断开后计时、重启、恢复网络 | 事实保留，完成记录只写一次 |
| T04 | 后端已提交但响应丢失 | 重试同操作返回回执，不重复计数 |
| T05 | 本地事实/队列/确认/游标各提交点故障 | 重放后无漏上传、漏拉取或错误确认 |
| T06 | 同项目连续离线改名、改色 | 操作依赖正确，最终结果可解释 |
| T07 | 两设备同时改项目、排序、归档 | 原子提交，冲突可处理，无半组修改 |
| T08 | 拉取分页期间其他设备持续写入 | 上界固定，本轮及后续均无漏变更 |
| T09 | snapshot 分页期间持续修改 | 快照一致，后续变化可增量补齐 |
| T10 | 服务端提交顺序与序号并发 | 游标不跳过迟提交变化 |
| T11 | 同名不同 ID、同 ID 不同内容 | 明确预览/冲突，无静默覆盖 |
| T12 | 项目删除与另一设备活动会话/离线上传 | 活动计时继续，未上传事实可恢复 |
| T13 | 自动倒计时结束，页面未主动 stop | 产生且只产生一条完成上传任务 |
| T14 | 跨午夜、暂停、设备时钟异常 | 保持当前时间与统计契约 |
| T15 | 迁移每个阶段中断或分块重复上传 | 可续传，数据不重不漏 |
| T16 | A 切换 B 后旧网络响应到达 | 不写错账号，不刷新错页面 |
| T17 | access/refresh 过期、并发刷新、退出 | 队列保留，凭证流程正确 |
| T18 | 篡改空间、实体、分页令牌和导出任务 ID | 无法读写他人数据 |
| T19 | 清空账号后旧设备回来 | 旧 generation 被隔离，不回灌 |
| T20 | 同步游标过期或服务端恢复备份 | 保全未上传数据并正确全量恢复 |
| T21 | 配色、主题、本机轮次与引用偏好 | 项目颜色一致，设备偏好不误同步 |
| T22 | 慢网、冷启动、后端不可用、存储接近上限 | 本地计时不等网络，错误真实可见 |
| T23 | 同步大数据时操作计时与统计 | 真机无明显新增卡顿，有测量结果 |
| T24 | 数据库备份恢复演练 | 可恢复事实、操作回执与同步一致性 |
| T25 | 小程序上传包检查 | 不含 server/node_modules、测试或密钥 |
| T26 | 老 API/旧客户端与新 schema | 明确兼容或升级提示，不毁坏数据 |

测试应针对数据一致性、事务、故障恢复与真实用户流程，避免仅镜像实现的无意义测试。适当复用 memory adapter 的故障注入能力。

## 15. 云部署与预算核实

执行 AI 在部署前核实官方控制台和文档，禁止把某个优惠套餐价直接当总价。

需要确认：

- 云托管、PostgreSQL 是否对当前账号和地域可用，标准连接权限是否具备。
- 后端与数据库尽量同地域，内网或支持的受控连接路径。
- 容器启动端口、健康检查、运行身份、日志与环境变量。
- HTTPS 公网入口供小程序和未来 App 使用；小程序采用统一请求适配，默认 wx.request，不让核心协议依赖 callContainer。
- 自有域名是正式环境优先项，测试可先用平台域名；域名手续以实际地域和官方要求核实。
- 小程序请求合法域名与真机网络配置。
- 数据库连接池、服务实例扩容上限、流量与日志额度。
- 最小实例为零会有冷启动；需要常驻实例时列出额外费用，再根据测量选取。
- 数据库若自动暂停同样可能增加首请求等待，记录该配置。
- 数据库备份策略、恢复权限、备份保留期和实际恢复演练。
- 测试与正式环境分别使用凭证和数据库。

预算表分别列：云托管计算、数据库、网关、流量、日志、备份、域名及可选常驻资源。按低使用量与增长后两档给出依据，不虚构能支持多少用户。

数据库 TLS 及证书按实际连接要求配置，不为了跑通连接无条件关闭证书校验。

如果当前 CloudBase PostgreSQL 不能满足标准连接或可用性要求，记录证据并提出托管 PostgreSQL 替代部署；保持标准数据库与通用后端，不偷偷改成文档库或买另一台服务器。
